Overall: Amber

The model and the platform are sound. Live scores need feature alignment before they can block payments on their own.

The XGBoost champion ranks fraud at 0.956 on the project's random split and 0.889 on future days, and the pipeline delivers every event exactly once at 63 ms p95. The gap sits in one place: the live feature code gives the model inputs that match training on only 7 of its 43 features, so live ranking quality drops to 0.574. That is fine for the demo and for routing cases to an analyst, but not yet for automatic blocking. Every cause is identified, and a three-phase fix has been measured on the same transactions.

Findings register

What the evidence shows, by severity

F-01
Critical

Training–serving skew in the live feature code

Finding
The live path builds 36 of 43 features differently from training. Causes: 9 code defects, 17 fields missing from the Avro event, and 10 card-history counters that need a feature store.
Impact
Live ROC-AUC 0.574. At production thresholds the live path catches 3.1% of fraud and lets $612,109 of $639,135 through.
Evidence
R01, R02, R04–R07
F-02
High

The headline score is optimistic for future transactions

Finding
Tested on later days, the same recipe scores 0.889, not 0.956. Recall falls from 83.9% to 63.1% and PR-AUC from 0.709 to 0.450.
Impact
Quoting 0.956 overstates expected performance by about 0.066 ROC-AUC.
Evidence
R10, R15

Decision record

Architecture decisions from this audit

D-01 · Keep

XGBoost stays the champion

Higher recall (83.9% vs 77.8%) and the only model to pass all four gates. Resolves the model choice with evidence.

D-02 · Restrict

No automated BLOCK from live scores yet

Live scores route to human REVIEW until the live path passes the quality gate on out-of-time data. Addresses F-01.

D-03 · Fix

Close the skew in three measured phases

Code fixes, then event schema v2, then a feature store. Each phase is re-measured with this harness before it ships. Addresses F-01, F-06, F-08.

D-04 · Standardise

Out-of-time evaluation is the reference

Quote 0.889 as expected performance. Fit encodings on training data only and early-stop on a validation slice. Addresses F-02, F-07.

D-05 · Gate

Four quality gates on every change

ROC-AUC ≥ 0.90, recall ≥ 0.80, false-positive rate ≤ 0.08 and precision ≥ 0.30, run automatically before any model or feature change ships.

D-06 · Calibrate

Production thresholds, re-calibrated per phase

0.50 / 0.85 for real customers. Demo thresholds stay labelled demo-only. Re-calibrate after each fix phase, because the scores shift. Addresses F-03.

D-07 · Monitor

Scheduled drift and segment monitoring

A daily Evidently drift report on features and score, segment recall by product, and a retraining trigger. Addresses F-04, F-05.

D-08 · Extend

Widen the audit after the demo

Velocity rule, blocklist, DistilBERT and live latency from a read-only database export; Groq and Gemini within their free-tier budgets.

Scope

What this audit covers, and what it does not

Covered

  • XGBoost champion and Random Forest challenger
  • The live scoring path: Avro event, live features, model
  • Out-of-time generalisation and evaluation method
  • Threshold policies and segment behaviour
  • Data quality of the training data and of the pipeline export
  • Delivery integrity and latency from the pipeline export
  • Drift between the first and last 30 days

Not covered here

  • Velocity rule and blocklist accuracy
  • DistilBERT text check, SHAP narratives, Groq and Gemini
  • Failover, Kafka resilience and the Hetzner server's own data

These need a read-only database export, or use the free-tier AI budgets. They are scheduled under D-08.

Method and trust

Why these numbers can be relied on

Self-checks that passed

  • The laptop replica re-scored 4,692 pipeline events with a largest difference of 5 × 10⁻⁹.
  • Offline results reproduce the project's documentation exactly: 0.9562, recall 0.8393, FPR 0.0656.
  • The what-if copy with no fixes equals the project's live features on all 5,078,644 values.
  • An independent rebuild of the training features matches the project's test set exactly.

Safeguards

  • Every script stops if the project's code changes. It stayed unchanged throughout.
  • No cache files, models or data were written into the project.
  • No connection to the server, Kafka, Redis or the database. 0 Groq and 0 Gemini calls.
  • Evidently runs in its own environment, separate from the project's.
